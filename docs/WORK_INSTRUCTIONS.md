# 구현 작업지시서

작성일: 2026-10-12 · 기준 문서: [설계서](DESIGN.md)

## 1. 작업 목표와 경계

공유 끝·시작 이미지를 사용하는 생성 영상의 연결부를 제어하고, 초반 핵심 동작을 보호하며 후반부를 압축하는 Python 도구를 단계별로 구현한다.

현재 요청은 설계 보완과 코드 구현·독립 검증, 이후 실제 3클립 11초·2클립 8초 결과 제작이다. 문서 작성만으로 구현 완료라고 표시하지 않는다. GitHub 푸시·PR 생성·업로드는 사용자의 명시적 요청 전에는 수행하지 않는다.

기존 체크아웃을 사용한다. 사용자 파일·원본 영상·기존 변경을 보존한다. 단계별 실제 결과와 미검증 항목을 분리해 보고한다.

### 역할과 책임

구현 작업자와 검증 작업자는 별도로 배정한다. 구현 담당의 자체 테스트만으로 독립 검증을 대신하지 않는다. 조율 담당이 작업 범위와 결과를 관리한다.

| 역할 | 책임 | 인계 산출물 |
| --- | --- | --- |
| 조율 담당 | 작업 단위·선행 조건·완료 기준 지정, 담당 배정, 결과 취합, 수정·재검증 관리, 단계 진행 판단 | 작업 할당서, 진행 상태, 사용자 보고 |
| 구현 작업자 | 지정 범위의 코드·테스트·실행 안내 작성, 자체 테스트, 검증 결함 수정 | 변경 파일, 실행 명령, 입력·설정, 자체 테스트 결과, 출력 경로, 알려진 한계 |
| 검증 작업자 | 요구사항과 완료 기준에 따른 독립 실행, 오류·경계 사례 검사, 비교 영상 검토, 결함 보고 및 재검증 | 기준별 판정, 실행 증거, 재현 가능한 결함 목록, 미검증 항목 |

검증 작업자는 제품 코드를 직접 수정하지 않는다. 필요한 독립 테스트·검증 보고서는 작성할 수 있으며 조율 담당이 파일 범위를 구분한다. 구현 작업자에게는 결함의 재현 절차와 증거를 전달한다. 검증에 맞추기 위해 요구사항이나 통과 기준을 임의로 낮추지 않는다.

### 작업 순서와 인계 절차

작업 순서는 **A1 → A2 → A3 → A4 → B1 → B2 → C → D**다. 독립 검증은 A4에만 수행하는 것이 아니라 각 작업 단위에서 수행한다. B·C·D는 필요하면 작은 단위로 나누되 선행 조건은 유지한다.

1. 조율 담당이 작업 ID, 구현·검증 담당, 범위, 수정 가능 파일, 선행 조건, 완료 기준을 지정한다.
2. 구현 작업자가 구현과 자체 테스트를 완료하고 인계 자료를 제출한다.
3. 조율 담당이 검증할 코드 상태를 고정한다. 커밋이 없다면 변경 목록과 파일 해시 등으로 식별하며, 검증 중 해당 파일을 동시에 수정하지 않는다.
4. 검증 작업자가 전달된 결과를 읽는 데 그치지 않고 직접 명령을 실행한다. 정상·오류·경계 사례를 기준으로 확인하고 필요한 독립 검사를 추가한다.
5. 실패 항목은 구현 작업자에게 반환한다. 구현 작업자가 수정 내용과 영향 범위를 제출하면 검증 작업자가 실패 사례와 영향받는 기존 기능을 재검증한다.
6. 조율 담당이 최종 검증 대상과 결과가 일치하는지 확인하고 사용자에게 보고한다. 필수 기준이 통과한 작업만 다음 순서로 진행한다.

검증 중 코드가 바뀌면 기존 통과 결과를 새 코드에 그대로 적용하지 않는다. 공유 작업 공간에서는 같은 파일을 동시에 편집하지 않으며, 실행 중인 출력 파일도 서로 덮어쓰지 않도록 작업별 경로를 사용한다.

### 판정과 단계 진행

- **통과:** 해당 작업 단위의 필수 기준을 모두 실행하여 충족했다.
- **수정 필요:** 재현 가능한 결함이나 필수 기준 실패가 있다. 수정 후 재검증한다.
- **검증 대기:** 실제 클립·실행 환경 등 필수 입력이 없어 판단할 수 없다. 사유와 필요한 입력을 기록한다.

검증 대기를 통과로 취급하지 않는다. 가능한 독립 작업은 계속하되 필수 검증에 의존하는 다음 단계는 진행하지 않는다. 실제 시각 품질의 최종 확인은 사용자에게 남기되, 2026-10-12 사용자 지시에 따라 이전 품질 확인 대기로 후속 코드 작업을 막지 않는다. 기술 검증을 통과하면 B1 → B2 → C → D를 순차 구현하고 실제 결과를 준비한다. 합성·기술 통과를 사용자 품질 승인으로 표시하지 않는다.

### 인계·결함 기록 양식

각 인계에는 작업 ID, 검증 대상 코드 식별 정보, 변경 파일, 실행 환경·도구 버전, 재현 명령, 입력·설정, 자체 테스트 결과, 결과 파일 위치, 미해결 항목을 기록한다. 커밋·GitHub 업로드는 인계의 필수 조건이 아니다.

결함마다 결함 ID, 관련 작업·완료 기준, 재현 절차, 기대 결과, 실제 결과, 로그·영상 경로와 문제 시점, 영향 범위, 수정 상태, 재검증 결과를 기록한다. 최종 보고에서는 자체 테스트와 독립 검증, 합성 영상 검증과 실제 영상 품질 확인을 구분한다.

## 2. 작업 A: 연결부 테스트 엔진

### 추가 필수 기능과 독립 검증 기준

아래 4개 기능은 설계서의 F1~F4와 같은 ID로 구현·결함·검증 보고서에서 추적한다. 작업 순서를 유지하며 지정된 단계에 포함한다.

| 기능 | 구현 시점 | 검증 작업자의 필수 확인 |
| --- | --- | --- |
| F1 원본 프레임 번호·시간 표시 | A2에서 기준 정보, A3에서 보정 매핑, B에서 변속 매핑 | 프레임 식별자가 있는 합성 입력의 실제 선택 프레임과 표시·보고서를 대조한다. VFR·비영 시작 PTS와 제거·반복 프레임을 포함하며 최종 제작본에는 표시가 없어야 한다. |
| F2 원본·보정본 동기 비교 | A3 비교 영상, A4 검증, D 조작 UI | 같은 경계가 상대 시간 0에 정렬되고 양쪽 재생 시계가 일치하는지 확인한다. 길이 차이·범위 밖 표시·각 원본 위치를 검사하고 비교용 추가 변속이 없는지 확인한다. |
| F3 클립별·연결부별 보정 제외 | A3 연결부 제어, B 시간 압축, C 설정 저장 | 클립·경계 활성 조합별 실제 프레임 매핑을 대조한다. 제외 클립이 삭제되지 않고, 인접 경계 보정이 억제되며, 경계만 끌 때 클립 압축은 유지되어야 한다. 제외 클립과 목표 시간 충돌은 오류여야 한다. |
| F4 전체 타임라인 시간 검증 | B, C 보고서, D 표시 | 개별 목표와 합계 모두 한 출력 프레임 이내인지 디코딩 결과로 확인한다. 소수 목표 시간·혼합 FPS·여러 경계 중복 제거·보정 제외를 조합해 누적 오차와 프레임 공백·겹침을 검사한다. |

F1·F2의 원본 시간, 출력 시간, 경계 상대 시간을 혼용하지 않는다. F3의 제외는 출력 형식 정규화까지 생략하는 의미가 아님을 실행 안내에 명시한다. F4가 실패하면 결과 파일 생성 여부와 무관하게 검증 실패로 보고한다.

### A1. 기반 준비

1. 저장소 지침, Python·FFmpeg·ffprobe 버전, 사용 가능한 인코더를 확인한다.
2. 격리된 Python 환경과 재현 가능한 의존성 정의를 만든다. NumPy·OpenCV 등 실제 사용하는 패키지만 설치한다.
3. 설계서의 모듈 구조, CLI, 오류 처리, 작업별 출력·임시 경로를 구현한다.
4. 원본 변경 금지 및 기존 결과 덮어쓰기 방지를 구현한다.

완료 조건: CLI 도움말과 필수 도구 진단이 동작하고 누락된 도구·잘못된 입력에 명확한 실패 코드를 반환한다.

### A2. 입력과 기준 영상

1. 순서가 지정된 3~4개 클립을 받는다. 테스트 편의를 위해 2개 이상도 허용한다.
2. 메타데이터·실제 프레임 타임스탬프·오디오 유무를 분석한다.
3. FPS·해상도·화면 비율 차이 처리 정책을 명시한다.
4. 보정 없는 연결본과 경계별 앞뒤 비교 구간을 출력한다.
5. F1의 클립 ID·0부터 시작하는 원본 표시 프레임 번호·PTS 기반 시간을 수집하고 진단 출력에 표시한다.

완료 조건: 입력 순서가 보존되고 모든 결과가 디코딩 가능하며 원본 파일 해시가 변하지 않는다.

### A3. 분석과 조절

1. 경계 프레임 유사도, 반복 정지, 움직임 속도·방향과 신뢰도를 계산한다.
2. 중복 프레임 처리와 국소 시간 매핑을 각각 독립적으로 켜고 끌 수 있게 구현한다.
3. 연결부 창 크기·강도와 시간 매핑의 수학적 의미 및 허용 범위를 문서화한다.
4. 단조성·시작과 끝 대응·길이 변화를 검증한다.
5. 원본 연결본, 보정 후보, 경계별 비교, 측정 보고서를 저장한다.
6. F1의 출력→원본 프레임 매핑과 F2의 경계 정렬 비교 영상을 구현한다.
7. F3의 클립별·경계별 보정 제외와 우선순위를 구현하고 실제 적용 여부·제외 사유를 보고한다.

자동 적용 제한: 의도된 정지와 중복을 구별하기 어려우면 후보만 제안한다. 흐름 방향 충돌이나 형태 변형을 배속만으로 해결했다고 주장하지 않는다. 디졸브나 전체 안정화를 기본값으로 넣지 않는다.

### A4. 검증과 단계 종료

- 합성 3~4클립 시퀀스로 정상 연결, 중복, 속도 차이 및 보정 부적합 사례를 검증한다.
- 제어값을 바꿨을 때 실제 출력 프레임 스케줄·영상이 달라지는지 확인한다.
- 단순 성공 종료나 파일 생성만 확인하지 말고 경계의 동작과 끝 프레임을 검사한다.
- 구현 이후 실제 클립 3~4개를 받아 정상 속도로 원본·보정본을 비교한다.
- F1~F3의 1단계 검증 기준을 독립 실행하고, 실제 결함은 클립 ID·원본 프레임·출력 시간으로 기록한다.

산출물: 실행 코드, 자동 테스트, 실행 안내, 합성 결과와 측정 보고서. 실제 클립이 없으면 “기능 검증 완료 / 실제 품질 미검증”으로 보고한다. 기술 검증 통과 후 B1로 진행한다. 실제 품질 확인은 별도 상태로 추적한다.

## 3. 작업 B1: 목표 길이와 후반 압축

1. 클립별 목표 시간·보호 시간·배속 상한·전환 폭을 CLI에서 받는다.
2. 보호 구간 이후 부드럽게 가속하는 곡선을 계산하고 목표 길이에 대한 해를 구한다.
3. 작업 A의 국소 시간 조절을 최종 시간 매핑에 합성한다.
4. CFR 출력 프레임 스케줄을 만들고 실제 마지막 표시 프레임이 출력에 포함되는지 확인한다.
5. 공유 경계 중복 처리와 각 클립·전체 프레임 예산을 함께 검사한다.
6. 보호 구간을 유지할 수 없거나 배속 상한을 넘으면 거절한다. 무단 설정 완화는 하지 않는다.
7. 오디오 제외를 명시한다. 동기화 처리 전에는 오디오 유지 요청을 지원하지 않는다고 반환한다.
8. F1~F3를 변속 후에도 유지한다. 보정 제외 클립에 원본과 다른 목표 시간을 지정하면 설정 충돌로 거절한다.
9. F4의 전체·클립별 프레임 예산을 계산하고 경계 중복 처리 후 재배분한다. 최종 디코딩 결과와 비교하여 타임라인 보고서를 만든다.

필수 테스트:

| 사례 | 확인 내용 |
| --- | --- |
| 10초 → 4초, 초반 2초 보호 | 보호 구간 1배속, 후반 곡선, 목표 길이 |
| 6초 → 5초, 초반 3초 보호 | 완만한 압축과 연결부 |

| VFR·비영 시작 PTS·다른 FPS | 시간 정규화와 끝 프레임 |

| 소수 목표 시간·혼합 FPS·중복 제거의 조합 | 클립별 반올림 오차의 누적 방지, 전체 오차 한 출력 프레임 이내 |
| 보정 제외 클립·경계와 시간 압축의 조합 | F3 우선순위, 설정 충돌, 끝 이미지·보호 구간과 F4 동시 충족 |

기술 완료 조건: 목표 오차 한 출력 프레임 이내, 첫·끝 이미지 대응 확인, 보호 구간 유지. 정상 속도에서 핵심 동작 및 연결부의 사용자 품질 확인은 별도 상태로 남기고 후속 코드 구현을 계속한다. 손실 인코딩 출력은 픽셀 완전 일치 대신 프레임 스케줄 추적과 허용 오차를 둔 영상 비교로 검증한다.

### B1 실행·판정 보완

사용자가 초반 보호 시간을 지정하지 않은 첫 실제 후보는 1초를 명시적 초기 설정으로 사용한다. 이는 핵심 동작 자동 판별 결과가 아니며 CLI·JSON·UI에서 변경할 수 있어야 한다. 배속 상한과 수학적 제약을 만족할 수 없으면 오류로 반환하고 보호 구간을 몰래 바꾸지 않는다. 목표가 원본과 같으면 시간 압축은 생략한다. 경계 보정의 속도 계획은 원본 움직임과 시간 매핑의 경계 배속을 함께 사용한다. 10→3초 압축 클립과 4→4초 보호 클립의 접속에서 조절 방향이 원본 속도만 사용했을 때와 반대로 되는 회귀 사례를 검증한다.

완료 기준에 실제 3·4·4초의 11초 예산 및 4·4초의 8초 예산 합성 테스트를 포함한다. 경계 보정과 보호 구간이 충돌하면 보호 구간을 우선하여 해당 보정을 제외하고 이유를 기록한다. 중복 제거를 적용할 때는 보호 구간·끝 이미지·프레임 예산을 동시에 검증하며 불가능하면 적용하지 않고 보고한다.

### B2: 클립 내부 움직임 검토·선택 보정

1. 저해상도 순차 분석으로 반복 프레임·짧은 정지·급격한 속도 변화의 의심 구간을 표시한다. 구간 ID, 원본 시작·끝 시간, 종류, 측정 근거와 한계를 보고한다.
2. 의도된 정지나 형태 왜곡을 자동으로 고칠 수 있다고 주장하지 않는다. 형태 변화 복원·카메라 공간 안정화는 이번 시간 기반 보정 범위에서 제외한다.
3. 후보 구간 전후를 원본과 나란히 비교 출력한다. 기본은 미선택이며 명시적으로 선택한 ID만 적용한다. 미선택·제외 구간을 수정하지 않는다.
4. 선택 구간에는 시작·끝 고정의 단조 시간 매핑으로 국소 속도 변화 완화 후보를 만든다. 실제 선택 프레임이 달라지지 않으면 무효과로 보고한다.
5. B1의 보호 구간·배속 상한·목표 길이·끝 프레임·F3 제외와 합성 검증한다. 보호 구간과 겹치는 후보는 적용을 거절하거나 제외 사유를 기록한다. 결과 길이는 유지한다.
6. JSON에 후보 ID만 저장해 다른 원본에 오적용하지 않도록 원본 해시와 분석 식별 정보를 함께 저장하고 일치 여부를 검증한다.

검증: 합성 정지·반복·속도 변화 탐지, 정상 이동의 과도한 탐지 여부, 기본 미적용, 선택·제외 우선순위, 원본 변경 후 오래된 선택 거절, 후보 비교 원본 프레임 대응, B1 합성 시 목표 길이·보호 구간 보존. 실제 자연스러움은 미검증 상태로 별도 표시한다.

## 4. 작업 C: JSON과 일괄 처리

1. A·B1·B2에서 검증한 옵션을 바탕으로 JSON 스키마 버전 1을 확정한다.
2. 설정 파일 기준 상대 경로, 클립 순서, 목표 시간, 보호 구간, 경계 옵션을 파싱한다.
3. 파일 누락, 중복ID, 비정상 수치, 알 수 없는 키, 순서 불일치를 실행 전에 검증한다.
4. 클립 출력과 전체 연결본, 작업 설정, 도구 버전, 성공·실패 보고서를 저장한다.
5. 실패한 클립을 건너뛴 결과를 전체 성공으로 표시하지 않는다. 실패 범위와 재실행 방법을 제공한다.
6. 동일 설정 재실행 시 기존 결과를 훼손하지 않으며 설정과 입력이 추적 가능해야 한다.
7. 클립·경계 보정 활성 값을 저장·복원하고, 생략 기본값 및 false의 우선순위를 검증한다. F1의 매핑, F2의 비교 기준, F3의 실제 적용 여부, F4의 배치·길이·오차를 결과 보고서에 포함한다.

B2 분석 결과의 출처와 구간별 선택·제외를 JSON에서 읽고 저장한다. 기본 선택은 없으며 잘못된 구간 ID·해시·겹치는 설정을 실행 전에 검증한다.

완료 조건: 정상·잘못된 JSON 통합 테스트, 공백·한글 경로, 부분 실패·취소, 출력 충돌 테스트 통과. 입력 JSON 예제와 실행 안내 제공.

## 5. 작업 D: UI

기본 엔진 검증 후 대상 OS와 실제 사용 흐름을 확인하여 UI를 구현한다.

1. 클립 추가·순서 변경 및 원본·목표 길이 표시.
2. 보호 구간·후반 속도 곡선 편집.
3. 연결부 정상 속도 비교 재생 및 옵션 조절.
4. JSON 불러오기·저장과 출력 경로 선택.
5. 작업 진행률·취소·실패 원인·결과 접근.
6. F1 위치 표시, F2 공통 재생·탐색·일시정지·경계 반복·프레임 단위 앞뒤 이동, F3 개별 보정 토글, F4 최종 시작·끝 시간과 총길이·오차 표시.

7. 내부 의심 구간 목록·원본 시간·근거 표시, 구간별 비교 및 적용·제외 선택을 제공한다. 선택 결과를 JSON에 저장·복원하고 오래된 분석은 거절한다.
8. 제작 Master JSON의 `records[].edit_duration_s`를 로컬 MP4 파일명의 장면·컷과 대응시켜 Target에 채운다. 클립 경로·순서·출력 경로와 보정 선택은 보존하고, 누락·중복·시간 불일치는 적용 전에 거절한다. 가져온 뒤 실제 실행용 JSON은 별도로 저장한다.

UI 독립 검증: 양쪽 비교 화면을 탐색·반복·프레임 이동해 동기가 유지되는지 확인한다. 보정 토글을 바꿔 JSON으로 저장·재로드한 뒤 엔진 결과와 일치하는지 확인한다. 설정 변경 후 이전 출력이 최신으로 표시되지 않는지 검사한다.

완료 조건: UI 설정이 엔진에 동일하게 전달되고 렌더링 중 화면이 응답한다. 실제 클립으로 불러오기부터 최종 출력까지 수행한다. Windows 실행 파일이 필요하면 Windows에서 별도 빌드·검증하며 Linux에서 만든 실행 파일을 Windows용이라고 표시하지 않는다.

## 6. 단계별 보고 형식

- 작업 ID, 구현·검증 담당, 검증 대상 코드 식별 정보.
- 구현한 기능과 실행 명령.
- 사용한 입력과 적용 설정.
- 자동 검사 통과·실패·미실행 항목.
- 합성 영상과 실제 영상의 검증 상태.
- 원본·보정본·보고서의 저장 위치.
- 확인된 한계와 다음 단계 진입 여부.
- 독립 검증 판정, 결함별 수정·재검증 결과, 필요한 사용자 품질 확인 상태.
- F1~F4별 적용 단계, 검증 증거, 통과·실패·미실행 상태와 타임라인 오차.

분석 수치만으로 “꿀렁임 완전 제거”를 선언하지 않는다. 실제 품질 검토가 필요한 시점에는 비교 가능한 결과물을 먼저 준비한다. 사용자가 GitHub 업로드를 지시하면 그 시점의 변경 내역과 포함 파일을 확인하고, 원본 영상·대용량 생성물·비밀정보가 섞이지 않도록 업로드 범위를 점검한 뒤 수행한다.

## 7. 이번 실제 결과 목표와 진행 순서

코드 구현·독립 검증을 우선한다. B1 → B2 → C → D 후 기존 원본을 사용해 다음 두 결과를 만들고 실제 디코딩 길이·원본 해시·선택 설정을 보고한다.

- 앞 묶음: SC01 01-02 → 01-03 → 01-04, 목표 3·4·4초, 총 11초.
- 뒤 묶음: SC01 01-05 → SC02 02-01, 목표 4·4초, 총 8초. 장면 번호가 달라 공유 끝 이미지라고 가정하지 않는다.

실제 내부 보정은 사용자가 선택하기 전까지 미적용으로 두고 의심 구간·비교 후보를 별도로 제공한다. 목표 시간 압축 후보는 명시한 초반 1초 보호 설정으로 제작한다. 기술 검증과 사용자 시각 품질 확인을 구분하며, GitHub 업로드는 별도 지시가 있을 때만 수행한다.


## 추가 작업: 목표 시간 확장

구현자는 기존 B1 시간 매핑에 보호구간 유지 후 감속 확장을 추가한다. 4→5초/24fps에서 120프레임, 첫 1초 실시간, 마지막 source frame 보존, 매핑 단조 증가, 부드러운 속도 전환과 분산 프레임 재사용을 확인한다. 양의 속도 불가능/보정 비활성화 충돌은 JSON 사전검사에서도 거절한다. 최대속도 상한과 UI 곡선을 확장 모드에 맞춘다. 기존 압축·경계 유효속도 회귀를 실행한다.

구현자 자체 검증 후 독립 검증자에게 동결 인계한다. 실제 Master 재처리는 독립 검증 이후 진행하며 기존 산출물은 덮어쓰지 않는다. 보간 없는 저속 재생 품질 한계를 보고한다. 앞서 사용자가 요청한 소스 공개 상태를 유지하도록 검증 후 GitHub main에 반영한다.
