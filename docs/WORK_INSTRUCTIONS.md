# 구현 작업지시서

작성일: 2026-10-12 · 기준 문서: [설계서](DESIGN.md)

## 1. 작업 목표와 경계

공유 끝·시작 이미지를 사용하는 생성 영상의 연결부를 제어하고, 초반 핵심 동작을 보호하며 후반부를 압축하는 Python 도구를 단계별로 구현한다.

현재 요청의 산출물은 설계서와 작업지시서다. 이 문서에 적힌 구현 작업은 후속 구현 단계의 지시이며, 문서 작성만으로 완료했다고 표시하지 않는다. GitHub 푸시·PR 생성·업로드는 사용자의 명시적 요청 전에는 수행하지 않는다.

기존 체크아웃을 사용한다. 사용자 파일·원본 영상·기존 변경을 보존한다. 단계별 실제 결과와 미검증 항목을 분리해 보고한다.

## 2. 작업 A: 연결부 테스트 엔진

### A1. 기반 준비

1. 저장소 지침, Python·FFmpeg·ffprobe 버전, 사용 가능한 인코더를 확인한다.
2. 격리된 Python 환경과 재현 가능한 의존성 정의를 만든다. NumPy·OpenCV 등 실제 사용하는 패키지만 설치한다.
3. 설계서의 모듈 구조, CLI, 오류 처리, 작업별 출력·임시 경로를 구현한다.
4. 원본 변경 금지 및 기존 결과 덮어쓰기 방지를 구현한다.

완료 조건: CLI 도움말과 필수 도구 진단이 동작하고 누락된 도구·잘못된 입력에 명확한 실패 코드를 반환한다.

### A2. 입력과 기준 영상

1. 순서가 지정된 3~4개 클립을 받는다. 테스트 편의를 위해 2개 이상도 허용한다.
2. 메타데이터·실제 프레임 타임스탬프·오디오 유무를 분석한다.
3. FPS·해상도·화면 비율 차이 처리 정책을 명시한다.
4. 보정 없는 연결본과 경계별 앞뒤 비교 구간을 출력한다.

완료 조건: 입력 순서가 보존되고 모든 결과가 디코딩 가능하며 원본 파일 해시가 변하지 않는다.

### A3. 분석과 조절

1. 경계 프레임 유사도, 반복 정지, 움직임 속도·방향과 신뢰도를 계산한다.
2. 중복 프레임 처리와 국소 시간 매핑을 각각 독립적으로 켜고 끌 수 있게 구현한다.
3. 연결부 창 크기·강도와 시간 매핑의 수학적 의미 및 허용 범위를 문서화한다.
4. 단조성·시작과 끝 대응·길이 변화를 검증한다.
5. 원본 연결본, 보정 후보, 경계별 비교, 측정 보고서를 저장한다.

자동 적용 제한: 의도된 정지와 중복을 구별하기 어려우면 후보만 제안한다. 흐름 방향 충돌이나 형태 변형을 배속만으로 해결했다고 주장하지 않는다. 디졸브나 전체 안정화를 기본값으로 넣지 않는다.

### A4. 검증과 단계 종료

- 합성 3~4클립 시퀀스로 정상 연결, 중복, 속도 차이 및 보정 부적합 사례를 검증한다.
- 제어값을 바꿨을 때 실제 출력 프레임 스케줄·영상이 달라지는지 확인한다.
- 단순 성공 종료나 파일 생성만 확인하지 말고 경계의 동작과 끝 프레임을 검사한다.
- 구현 이후 실제 클립 3~4개를 받아 정상 속도로 원본·보정본을 비교한다.

산출물: 실행 코드, 자동 테스트, 실행 안내, 합성 결과와 측정 보고서. 실제 클립이 없으면 “기능 검증 완료 / 실제 품질 미검증”으로 보고한다. 사용자 품질 확인 이후 작업 B로 진행한다.

## 3. 작업 B: 목표 길이와 후반 압축

1. 클립별 목표 시간·보호 시간·배속 상한·전환 폭을 CLI에서 받는다.
2. 보호 구간 이후 부드럽게 가속하는 곡선을 계산하고 목표 길이에 대한 해를 구한다.
3. 작업 A의 국소 시간 조절을 최종 시간 매핑에 합성한다.
4. CFR 출력 프레임 스케줄을 만들고 실제 마지막 표시 프레임이 출력에 포함되는지 확인한다.
5. 공유 경계 중복 처리와 각 클립·전체 프레임 예산을 함께 검사한다.
6. 보호 구간을 유지할 수 없거나 배속 상한을 넘으면 거절한다. 무단 설정 완화는 하지 않는다.
7. 오디오 제외를 명시한다. 동기화 처리 전에는 오디오 유지 요청을 지원하지 않는다고 반환한다.

필수 테스트:

| 사례 | 확인 내용 |
| --- | --- |
| 10초 → 4초, 초반 2초 보호 | 보호 구간 1배속, 후반 곡선, 목표 길이 |
| 6초 → 5초, 초반 3초 보호 | 완만한 압축과 연결부 |
| 목표 시간 = 원본 시간 | 불필요한 압축 생략 |
| 보호 시간 ≥ 목표 시간인 압축 | 사전 오류 |
| 필요한 배속이 상한 초과 | 명시적인 실행 불가 |
| VFR·비영 시작 PTS·다른 FPS | 시간 정규화와 끝 프레임 |
| 여러 클립 연결 | 개별·전체 길이, 중복 경계, 단조 PTS |

완료 조건: 목표 오차 한 출력 프레임 이내, 첫·끝 이미지 대응 확인, 보호 구간 유지, 정상 속도에서 핵심 동작 및 연결부 사용자 확인. 손실 인코딩 출력은 픽셀 완전 일치 대신 프레임 스케줄 추적과 허용 오차를 둔 영상 비교로 검증한다.

## 4. 작업 C: JSON과 일괄 처리

1. A·B에서 검증한 옵션을 바탕으로 JSON 스키마 버전 1을 확정한다.
2. 설정 파일 기준 상대 경로, 클립 순서, 목표 시간, 보호 구간, 경계 옵션을 파싱한다.
3. 파일 누락, 중복ID, 비정상 수치, 알 수 없는 키, 순서 불일치를 실행 전에 검증한다.
4. 클립 출력과 전체 연결본, 작업 설정, 도구 버전, 성공·실패 보고서를 저장한다.
5. 실패한 클립을 건너뛴 결과를 전체 성공으로 표시하지 않는다. 실패 범위와 재실행 방법을 제공한다.
6. 동일 설정 재실행 시 기존 결과를 훼손하지 않으며 설정과 입력이 추적 가능해야 한다.

완료 조건: 정상·잘못된 JSON 통합 테스트, 공백·한글 경로, 부분 실패·취소, 출력 충돌 테스트 통과. 입력 JSON 예제와 실행 안내 제공.

## 5. 작업 D: UI

기본 엔진 검증 후 대상 OS와 실제 사용 흐름을 확인하여 UI를 구현한다.

1. 클립 추가·순서 변경 및 원본·목표 길이 표시.
2. 보호 구간·후반 속도 곡선 편집.
3. 연결부 정상 속도 비교 재생 및 옵션 조절.
4. JSON 불러오기·저장과 출력 경로 선택.
5. 작업 진행률·취소·실패 원인·결과 접근.

완료 조건: UI 설정이 엔진에 동일하게 전달되고 렌더링 중 화면이 응답한다. 실제 클립으로 불러오기부터 최종 출력까지 수행한다. Windows 실행 파일이 필요하면 Windows에서 별도 빌드·검증하며 Linux에서 만든 실행 파일을 Windows용이라고 표시하지 않는다.

## 6. 단계별 보고 형식

- 구현한 기능과 실행 명령.
- 사용한 입력과 적용 설정.
- 자동 검사 통과·실패·미실행 항목.
- 합성 영상과 실제 영상의 검증 상태.
- 원본·보정본·보고서의 저장 위치.
- 확인된 한계와 다음 단계 진입 여부.

분석 수치만으로 “꿀렁임 완전 제거”를 선언하지 않는다. 실제 품질 검토가 필요한 시점에는 비교 가능한 결과물을 먼저 준비한다. 사용자가 GitHub 업로드를 지시하면 그 시점의 변경 내역과 포함 파일을 확인하고, 원본 영상·대용량 생성물·비밀정보가 섞이지 않도록 업로드 범위를 점검한 뒤 수행한다.
