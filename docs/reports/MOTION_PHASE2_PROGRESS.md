# 프레임 보간·공간 안정화 2차 진행 기록

시작: 2026-10-12. 범위: M4·M5, JSON/CLI/UI 연결 및 독립 검증.

현재 판정: **구현·독립 합성/렌더 기술 검증 통과**. 아래 기록은 실패·수정 이력을 포함한다.
최종 수치는 이 문서의 「최종 기술 검증」 절을 참고한다. 실제 영상의 시각 품질과 다른 영상
범주의 일반화는 별도 검증 사항이다.

선박 4개 비교 생성 완료: 목표 3·3·5·3초, 보간 적용 7·0·16·0프레임, 공간 안정화는
모두 보류했다. 따라서 실제 선박의 흔들림 제거 성공으로 해석하지 않는다. 640픽셀 미리보기의
동시 적용 렌더는 각각 약 32.1·10.7·37.4·21.6초이며 별도 검증 시간은 제외한다.
원본·코드 변경 없음, 정량 및 독립 감사 기록은 [실제 영상 기록](MOTION_PHASE2_REAL.md)을 참고한다.

## 작업 분리

- motion_engine: `interpolation.py`, 보간 단위 검사, 백엔드 조사, 실제 비교 자료.
- baseline: `stabilization.py`, 안정화 단위 검사.
- 주 작업자: 선택 설정, 스트리밍 렌더 연결, JSON/CLI/UI, 통합 검사.
- verify: 사전 고정 합격 기준과 별도 합성 정답, 독립 검증. 제품 코드 수정 없음.

## 구현

보간은 모델 다운로드 없이 동작하는 OpenCV CPU 방식이다. 교체 가능한 백엔드 인터페이스를 제공한다.
RIFE는 조사만 했으며 설치·가중치 검증·실행 또는 비교 성능 측정을 했다고 주장하지 않는다.
[공식 자료와 선택 근거](MOTION_PHASE2_BACKEND.md).

안정화는 원본 기준 카메라 경로의 작은 이동·회전을 평활화한다. 선형 팬을 유지하고 줌과 불확실한
추적은 보류한다. 일정한 내부 크롭과 양끝 페이드로 크롭 자체의 확대/축소 출렁임을 제한한다.
크롭 예산은 전체 가로/세로 제거 비율이며 사용자 값과 실제 역변환 모서리 범위를 함께 검사한다.

두 기능은 독립 선택이며 기본은 꺼짐이다. 적용 순서는 원본 안정화 → 목표 시점 보간이다.
보간의 컷·신뢰도 검사는 변환 전 원본을 기준으로 한다. 원본의 첫·끝·보호 프레임은 직접 보존한다.
두 원본 프레임만 유지하는 렌더 버퍼와 한 프레임 쌍의 보간 캐시를 사용하며 처리 단계 진행률을 표시한다.
결과에는 양쪽 원본 번호/시각, 보간 비율, 공간 변환, 적용/미적용 사유를 기록한다.

## 검증 상태

- 구현자 보간 단위 5개, 안정화 단위 4개 통과.
- JSON 호환·잘못된 옵션 거절·정확한 끝점/보호 구간·원본 복귀·실제 저장 작업 출력 통합 3개 통과.
- UI 옵션 저장/재읽기·결과 만료 표시 검사 1개 통과. 기존 JSON/CLI API 출력 동등성 검사 통과.
- [별도 검증 기준](../MOTION_PHASE2_VALIDATION.md)을 먼저 고정하고 제품 코드 동결 후 독립 평가 진행 중.
- 첫 독립 평가에서 보간은 9개 정상 쌍 중 6개에 실제 적용하여 오차·선명도 기준을 통과했다.
  안정화는 실제 흔들림을 컷으로 오인하여 효능 기준에 실패했다. 카메라 기하 정렬 후 컷을 판단하는
  `stabilization-v1.1`로 수정하고 재검증 중이며, 실패 자료와 같은 합격 기준을 유지한다.
- v1.1은 흔들림을 약 68% 줄였으나 최소 선명도 비율 0.773으로 고정 기준 0.8에 미달했다.
  v1.2는 표준 Lanczos8을 두 번의 분리 가능한 축 보간으로 구현하고 중간값을 float32로 보존한다.
  샤프닝을 추가하지 않았으며 6개 구현자 검사를 통과한 뒤 독립 재검증 중이다.
  640×360 재구성은 구현자 측정 약 0.406~0.499초/프레임, 프로세스 최대 약 50MB였다.
  CPU 품질/시간 절충이며 원본 해상도나 전체 파이프라인의 처리 속도를 보장하는 수치는 아니다.
  v1.1의 추가 독립 픽셀 노이즈 스트레스 손실도 기록에 남긴다(최소 약 0.704). 무손실 일반 보장이 아니다.
- 렌더러는 마지막 프레임을 받은 뒤에도 디코더 EOF와 종료 오류를 검사하도록 보완했다.
  마지막 프레임 뒤 오류가 나는 회귀 검사도 통과했으며 완성 결과로 잘못 공개하지 않는다.
- 실제 다양한 분야의 영상은 사용자가 없다고 확인했다. 합성 통과로 실제 범용 품질 검증을 대체하지 않는다.
- 이 실행 환경의 Windows QProcess 시작 실패는 1차 기록과 동일하게 별도 미검증이다. 엔진 직접 렌더와
  UI 데이터 검사는 작업 프로세스 실행/취소의 종단 검증을 대신하지 않는다.

## 이어서 진행한 통합 품질 검사

안정화 v1.2는 독립 합성 검사에서 흔들림 RMS 비율 0.318, 최소 원본 대비 선명도
0.846으로 개별 기준을 통과했다. 보간도 정상 9개 중 6개에 적용하여 개별 기준을 통과했다.
그러나 두 처리를 연결한 출력에서는 선명도 손실이 발견되어 완료 판정을 보류했다.

안정화 역변환과 보간 역좌표를 합쳐 원본에서 한 번만 색상을 재구성하도록 수정했다.
이후 독립 검사에서 길이 240프레임/12초, 비활성화 출력 일치, 보호 구간 보존,
흔들림·팬·줌 동작 기준은 통과했다. 원본 대비 선명도 하한 0.8은 아직 충족하지 못했다.
인코딩 전 흔들림 사례 0.640, 팬 0.842, 줌 0.970이며, 디코딩 출력은 각각
0.683, 0.748, 0.964였다. 보간 재구성과 출력 인코딩의 손실을 나누어 수정 중이다.

해석적 원본 정답에는 입력 영상에서 이미 사라진 세부 묘사가 포함되므로 해당 비교값은
진단용으로 보존한다. 최종 보존성 판정은 수신한 원본과 동일 시간표의 비활성화 출력에 대한
비율로 한다. 기준 0.8과 실패 기록은 유지한다. 상세 변경 이력은 독립 검증 계약·보고서에 있다.

시각 품질은 별도 판정한다. 독립 검사에서 발견한 결함은 기준을 낮추지 않고 수정 후 재검증한다.

## 최종 기술 검증

`cpu-flow-v1.2`는 양방향 흐름으로 이동을 검증하고 시간상 가까운 원본의 색을 한 번만
재구성한다. 두 원본의 서로 다른 샘플링 위상을 평균하면서 생기던 추가 손실을 줄였다.
보정된 최종/개별 영상은 `enhancement_fidelity_v1`(H.264 CRF1)으로 저장한다.
미리보기는 CRF18이며 파일 크기 증가와 미리보기의 용도를 README에 안내한다.

별도 작업자의 최종 고정 코드 검사:

- 단위·통합 19개 통과. UI 관련 별도 4개 통과.
- 보간 정상 9개 중 6개 실제 적용 및 품질 통과, 위험 사례 정확한 원본 복귀.
- 안정화 개별 흔들림 RMS 0.318, 선명도 0.846, 크롭 2.642%로 통과.
- 실제 인코딩 통합 240프레임/12초, 끝점·보호 구간 및 기존 비활성화 경로 보존 통과.
- 통합 흔들림 RMS 0.316, 팬 속도·줌 보존 통과.

| 통합 사례 | 인코딩 전 / 수신 원본 선명도 | 디코딩 후 / 같은 압축 조건의 무보정 영상 |
| --- | ---: | ---: |
| 흔들림 | 0.809720 | 0.806774 |
| 팬 | 0.976031 | 0.966722 |
| 줌 | 0.998823 | 0.996266 |

모두 기존 하한 0.8을 통과했다. CRF18 무보정 영상과 CRF1 후보를 비교하면 기존 압축의
테두리 잡음이 선명도 수치를 높이는 문제가 있었다. 별도 작업자가 무손실 RGB 출력조차
그 기준선에서 실패하는 것을 확인했다. 작업지시서의 동일 인코딩 조건에 맞춰 CRF1 무보정
대조군을 사용하고, 기존 CRF18 결과의 정확한 재현은 별도로 검사한다. 이전 수치·실패 기록과
진단은 삭제하지 않았다. 근거는 [독립 검증 보고서](MOTION_PHASE2_INDEPENDENT_VERIFICATION.md)에 있다.

기술 검증과 실제 영상의 체감 품질 승인은 다르다. 선박 4개 비교 결과는
[실제 영상 기록](MOTION_PHASE2_REAL.md)에 기록하며, 다른 영상 범주의 일반화 검증과
현재 실행 환경에서 막힌 GUI 작업 프로세스 종단 검증은 여전히 별도 확인 대상이다.
