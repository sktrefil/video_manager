# 2차 실제 영상 비교

2026-10-12. 독립 합성 기술 검증 통과 뒤 최종 코드를 고정하여 실제 원본 4개의 비교 출력을 완료했다. 실제 동영상 체감 품질은 사람의 검토가 필요하다.

재현 명령: `.venv/Scripts/python.exe tests/fixtures/run_real_motion_phase2.py`

M0에 기록한 서로 다른 앞쪽 4개 원본(01-02, 03-01, 03-03, 03-04)을 사용한다. 목표 시간은 각각 3·3·5·3초, 보호 구간은 1초다. 원본 SHA-256, 프레임 시각, 원본 경로를 유지하면서 640픽셀 폭 미리보기를 만든다. 시간 보정은 같은 기본 목표 시간표로 고정하여 픽셀 처리 단계의 차이를 비교한다.

4개 변형은 기본 결과, 보간만, 안정화만, 둘 다 적용이다. 안정화는 강도 0.7, 평활 구간 0.4초, 크롭 상한 5%를 사용한다. 2×2 비교 영상 배치는 왼쪽 위 기본 결과, 오른쪽 위 보간, 왼쪽 아래 안정화, 오른쪽 아래 둘 다 적용이다.

러너는 출력 길이·디코딩 프레임 수·보호/끝점 변형 여부, 변경 픽셀 프레임 수, 보간/공간 변형 적용 프레임 수와 보류 사유, 크롭 감사 정보, 처리 시간과 Python 프로세스 최대 메모리를 기록한다. 원본·제품 코드·결과 영상과 매핑의 해시도 기록한다. 실제 동영상의 체감 품질과 가는 구조·가림·잔상은 별도 사람 검토 대상으로 남긴다. 적용이 없으면 그대로 명시하고 개선 성공으로 표시하지 않는다.

기존 비활성 결과는 호환성을 위해 CRF18을 유지하고, 효과가 활성화된 최종 출력은 디테일 보존용 CRF1 프로필을 사용한다. 코덱 차이를 효과로 오인하지 않도록 별도 `baseline_fidelity.mp4`를 같은 CRF1 설정으로 만든다. 디코딩 비교는 이 같은 코덱 대조군을 사용한다. 또한 효과를 인코딩 전에 한 번 더 실행하여 원래 목표 시간 프레임의 RGB SHA-256과 비교하고, **실제로 달라진 프레임 수**를 기록한다. 이 추가 검사는 별도 시간으로 기록한다. 2×2 비교 영상은 네 CRF1 영상을 사용하고 CRF1으로 묶는다. 기존 진단 오버레이 영상은 품질 측정 자료로 사용하지 않는다.
