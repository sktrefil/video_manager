## 1. 목적과 적용 범위

현재 및 향후 제작 영상에 공통 적용하는 분석·선택 보정 파이프라인을 개발한다. 선박 영상은 첫 검증 자료이며 파일명, 장면 번호, 선박의 모양에 맞춘 알고리즘을 하드코딩하지 않는다. 인물·풍경·제품·빠른 동작과 정적인 영상으로 일반화 성능을 확인한다.

공통 흐름은 분석 → 문제 유형·신뢰도 판정 → 보정 후보 생성 → 원본·기존 방식·후보 비교 → 검증된 후보 적용이다. 정상 움직임, 의도된 정지·가속·카메라 이동을 보존한다. 모든 영상을 같은 강도로 보정하지 않는다.

이 문서는 기존 B2의 시간 기반 보정을 확장하는 후속 범위를 정의한다. 기존 설계에서 제외했던 프레임 생성은 M4의 선택적 보간에 한해 포함한다. 공간 보정은 M5의 제한된 전역 안정화에 한해 포함한다. 일반적인 형태 복원·영상 재생성은 포함하지 않는다.

실행 순서는 M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 통합 검증이다. UI 연결과 단위 검증은 각 단계에서 함께 수행한다. M6는 비교 실험과 채택 판단까지가 필수이며 특정 알고리즘의 채택을 미리 약속하지 않는다.

1차 사용 가능한 개선판은 M0~M3 및 해당 UI/배치 연결이다. 2차는 M4·M5와 통합 검증, 3차는 M6 평가 및 최종 M7이다. 모델 설치·다운로드 전 필요한 런타임, 라이선스, 가중치 버전/해시, GPU 메모리 요구량을 확인한다. 기본 CPU 분석 경로를 유지하고 선택적 GPU 기능이 없으면 기능 사용 불가 사유를 표시한다.

## 4. 보존 조건과 자동 적용 기준

- 개별 클립과 전체 목표 길이는 디코딩 결과 기준 각각 출력 1프레임 이내로 맞춘다. 중간 프레임 생성도 동일한 출력 프레임 예산을 사용한다.
- 시간 보정의 첫·마지막 원본 프레임 및 보호 구간은 유지한다. 공간/깜빡임 보정은 픽셀을 변경하므로 별도 선택으로 두며, 끝 이미지 고정이 요구되면 해당 변환을 비활성화하거나 양끝에서 항등 변환이 되도록 검증한다.
- 원본 파일은 수정하지 않는다. 원본 시각·프레임, 보간 양쪽 프레임과 비율, 적용 변환을 추적한다.
- 기본 모드는 분석과 검토 후보 생성이다. 자동 적용은 사용자가 해당 모드를 선택했고, 검증 자료에서 정한 신뢰도·품질 기준을 충족하고, 보호 조건을 모두 통과한 경우에만 허용한다.
- 품질 판정에는 목표 결함 감소와 부작용 검사를 모두 사용한다. 단순 프레임 유사도 증가나 움직임 감소만으로 통과시키지 않는다. 영상 정지·블러로 점수를 높이는 후보는 실패다.
- 모델이 달라지면 기존 분석·캐시가 그대로 유효한 것으로 처리하지 않는다. 원본, 분석 옵션, 모델 버전, 목표 시간, 보정 순서를 캐시 키에 포함한다.
- 후보 체인은 분석 → 선택적 안정화 → 제약된 시간 매핑/보간 → 선택적 깜빡임 보정 → 검증이다. 추적은 원본 기준으로 보존하고 좌표 변환을 연결한다. 개별 단계와 합성 결과를 모두 검사한다.

## 5. 검증 자료와 합격 조건

M0에서 임계값 조정용과 최종 평가용 자료를 분리한다. 평가 결과를 보고 유리한 임계값으로 다시 바꾸지 않는다. 수치 임계값과 성능 예산은 M0 결과로 확정해 코드 변경 전에 검증 명세에 기록한다. 데이터 없는 상태에서 정확도·처리 속도 수치를 약속하지 않는다.

- 합성 필수 사례: 일정 속도, 의도된 가속/정지, 전역 흔들림, 물체만 이동, 두 물체의 반대 방향 이동, 가림, 반복 프레임, 노출 변화, 장면 전환, 작은/큰 움직임. 결함 위치·정답 변환을 기록한다.
- 실제 필수 범주: 선박/파도, 인물, 풍경/카메라 이동, 제품/정적 구조, 빠른 동작. 범주별 정상·문제 구간을 최소 2개씩 확보한다. 없는 자료는 일반화 검증 대기로 기록하고 합성 테스트로 대체 완료하지 않는다.
- 현재 선박 영상에서 대표 구간 3~5개를 먼저 선정한다. 원본/기존 보정/개선 후보를 같은 목표 길이·FPS·인코딩 조건으로 비교한다. 원본은 원속도 참조와 목표 길이 기준선을 구분한다.
- 탐지: 유형별 정밀도·재현율, 정상 구간 오탐률, 판단 보류율을 기록한다. 정답이 모호한 실제 영상의 자동 판정은 참고값으로 명시한다.
- 품질: 추적 속도/가속 변화, 잔여 전역 흔들림, 크롭 비율, 반복 프레임, 움직임 정렬 후 밝기 변화, 선명도·잔상·물체 구조를 평가한다. 측정 모델과 동일 모델의 점수만으로 품질을 단정하지 않는다.
- 기술 필수: 목표 길이, 단조 매핑, 보호 구간, 컷 경계, 입력 변경 거절, 구형 JSON, 한글 UTF-8 경로, C:/D: 교차 저장, 오류·취소·재시작.
- 운영: 클립별 분석·미리보기·최종 출력 시간을 나눠 기록하고 CPU/GPU·RAM/VRAM·해상도·FPS를 함께 기록한다. 예상 시간은 산출 근거와 적용 범위를 표시한다.
- 기존 방식보다 시각 품질이 나빠진 대표 사례는 결함으로 남기고 해당 조건의 자동 적용을 막는다. 기술 통과와 사용자 시각 품질 확인을 별도로 보고한다.

## 6. 역할·수정 범위·인계

기존 작업지시서의 구현/독립 검증 분리 규칙을 따른다. 각 단계 시작 시 조율 담당이 담당자와 파일 범위를 배정한다. 검증자는 고정된 코드 상태에서 직접 실행하고 제품 코드는 수정하지 않는다.

예상 수정 범위는 `internal_motion.py`, `time_map.py`, `render.py`, `boundary.py`, `comparison.py`, `job_schema.py`, `ui/`, `progress.py` 및 신규 분석/보간 백엔드, 관련 테스트·문서다. 엔진·UI·검증 파일 소유권을 작업별로 구분하고 동시에 같은 파일을 수정하지 않는다.

단계별 인계물: 코드 식별 정보, 변경 파일, 재현 명령, 입력 해시, 분석/모델 버전, 설정, 원본/기존/후보 비교 영상, 정량 결과, 시간·메모리, 실패/미검증 사례, 독립 검증 판정. 문서 작성이나 모델 연결만으로 단계 완료를 선언하지 않는다.

## 7. 연구 근거와 미결정 항목

- [SEA-RAFT](https://github.com/princeton-vl/SEA-RAFT): 정밀 움직임 추정 비교 후보. 채택 전 CPU 기준선 대비 효과·비용 확인.
- [RIFE](https://github.com/hzwer/ECCV2022-RIFE): 선택적 임의 시점 보간 후보. 가중치·런타임·라이선스와 구조 보존 확인.
- [FFmpeg vidstab](https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform): 전역 안정화 비교 기준. 빌드 지원·크롭·연결 이미지 영향 확인.
- [FastBlend](https://github.com/Artiprocher/sd-webui-fastblend): 시간적 깜빡임 보정 연구 후보. 실제 적용 효과와 잔상 확인.

특정 모델 채택, 처리 속도, 개선율은 아직 미확정이다. 개발 범위는 위 단계로 정의하며, 구체적인 백엔드와 품질 임계값은 M0~M2의 측정 결과로 확정한다.
