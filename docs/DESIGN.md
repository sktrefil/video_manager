# 영상 클립 연결·시간 조절 도구 설계서

작성일: 2026-10-12 · 상태: 구현 전 설계안

## 1. 목적과 전제

영상 생성 단계에서 A→B, B→C, C→D처럼 앞 클립의 끝 이미지가 다음 클립의 시작 이미지로 사용된다. 이 클립들을 연결할 때 발생하는 작은 멈칫함이나 움직임 속도 차이를 줄이고, 생성된 길이와 다른 목표 재생시간에 맞춘다.

예를 들어 10초 클립을 4초로, 6초 클립을 5초로 조절한다. 핵심 동작이 주로 초반에 있으므로 전체에 같은 배속을 적용하지 않는다. 초반의 지정 구간을 보호하고 후반부를 중심으로 압축하며, 다음 클립으로 이어지는 끝 이미지까지 유지한다.

동일한 이미지를 생성 입력으로 사용했다는 사실과 실제 영상의 마지막·첫 프레임이 픽셀 단위로 같다는 사실은 구분한다. 디코딩한 프레임을 확인한다. 이미지가 같아도 카메라·물체의 이동 속도와 방향이 다르면 연결부가 어색할 수 있다.

## 2. 개발 순서와 단계별 범위

| 단계 | 구현 범위 | 다음 단계 진입 기준 |
| --- | --- | --- |
| 1 | 3~4개 클립 입력, 연결부 분석·조절, 비교 출력 | 연결부 기술 검증 통과, 실제 품질 확인은 별도 추적 |
| 2 | 초반 보호 및 후반 중심의 정밀 시간 압축 | B1 목표 길이·보호 구간 검증 → B2 내부 후보·선택 보정 검증 |
| 3 | JSON 작업 정의 및 일괄 처리 | 동일 설정 재실행, 입력 오류 처리, 결과 보고 검증 |
| 4 | 제작용 데스크톱 UI | 기본 기능 검증 이후 실제 제작 흐름 평가 |

각 단계에서 코드를 먼저 구현하고 합성 영상으로 기능을 검증한 뒤 실제 샘플로 품질을 평가한다. 이번 요청은 B1~D 코드를 먼저 진행한 뒤 실제 11초·8초 결과를 확인하는 순서다. 실제 샘플이 없다는 이유로 코드 구현을 미루지 않는다. 합성 테스트 통과를 실제 영상의 시각적 품질 통과로 간주하지 않는다.

첫 버전에서 제외: 영상 생성, 범용 다중 트랙 편집기, 자막 편집, AI 기반 핵심 동작 자동 판별, 프레임 생성·형태 복원, Windows 배포 패키지. 필요성이 확인되면 별도로 설계한다.

## 3. 기술 구성

- Python: 작업 관리, 시간 곡선 계산, 분석, CLI와 향후 UI 연결.
- FFmpeg / ffprobe: 미디어 정보, 디코딩·인코딩, 영상 연결 및 검증.
- NumPy / OpenCV: 프레임 차이, 특징점·움직임 분석. 분석용 저해상도 프레임 사용.
- PySide6: 4단계 UI 후보. 1~3단계에는 설치·구현하지 않는다.

GUI와 CLI가 같은 처리 엔진을 호출하도록 설계한다. 원본을 수정하지 않고 새 출력 디렉터리에 결과를 저장한다. 초기 출력은 CFR MP4, H.264, yuv420p를 기본 후보로 삼고 설치된 인코더를 검사한다. 해상도·FPS는 첫 클립을 기준으로 명시적으로 결정하고 다른 입력의 차이를 보고한다. 화면 비율이 다르면 기본은 패딩이며 임의로 자르거나 늘리지 않는다.

예정 구조:

```text
src/video_manager/
  cli.py             # 명령 입력
  probe.py           # 스트림·PTS·프레임 정보
  boundary.py        # 연결부 분석 및 조절 후보
  time_map.py        # 시간 매핑과 제약 검사
  render.py          # 프레임 선택·FFmpeg 실행
  pipeline.py        # 단계 실행, 취소, 실패 처리
  report.py          # 측정값 및 산출물 기록
  job_schema.py      # 3단계 JSON 검증
  ui/                # 4단계 화면
tests/
  fixtures/          # 합성 샘플 생성 코드
  unit/
  integration/
```

구조와 라이브러리 버전은 구현 시 검증하여 확정한다. 현재 저장소에는 실행 코드가 없다.

## 4. 1단계: 연결부 분석과 제어

### 입력·분석

클립 순서는 사용자가 지정하며 파일명 정렬로 추측하지 않는다. 각 클립의 길이, 시작 PTS, FPS, VFR 여부, 해상도, 오디오 유무를 수집한다. 각 경계의 앞뒤 구간을 추출한다. 기본 분석 창은 양쪽 0.5초로 시작하되 짧은 클립에서는 줄일 수 있게 한다.

분석 항목:

1. 마지막·첫 프레임 및 주변 프레임의 유사도와 정지 프레임 반복 여부.
2. 경계 전후의 광학 흐름 크기·방향 및 가능한 경우 전역 카메라 이동 추정.
3. 밝기·색 변화와 분석 신뢰도.

광학 흐름은 큰 물체 이동이나 형태 변화에 영향을 받는다. 단일 점수를 자연스러움의 정답으로 쓰지 않는다. 원본 측정값, 후보별 측정값, 비교 영상을 함께 제공한다.

### 조절 기능

- 보정 없는 단순 연결을 항상 비교 기준으로 출력한다.
- 경계의 중복 프레임은 인접 프레임과 함께 확인하고 제거 후보를 만든다. 의도된 정지 장면은 자동 삭제하지 않는다.
- 경계 앞뒤의 짧은 구간에 국소 시간 매핑을 적용해 움직임 속도 차이를 완화하는 후보를 만든다. 사용자는 적용 범위와 강도를 조절하고 끌 수 있다.
- 시작·끝을 고정한 단조 시간 매핑으로 경계 주변의 시간을 재분배한다. 방향 반전, 신규 프레임 생성, 무조건적인 끝 감속은 하지 않는다.
- 페이드, 디졸브, 전역 흔들림 안정화, 공간 정렬은 기본 적용하지 않는다. 진단상 필요하면 별도 후보로 검토한다.

1단계의 국소 속도 조절은 클립 전체 목표 시간 압축과 구분한다. 비교 후보에서는 가능한 한 길이를 유지하며 중복 제거 등으로 달라지는 프레임 수·길이를 보고한다. 흐름 방향이 충돌하거나 영상 형태가 달라지면 속도 조절만으로 해결할 수 없음을 표시한다.

### 출력

원본 연결본, 보정 후보 연결본, 경계별 전후 비교 영상, 분석 보고서, 사용한 설정을 출력한다. 경계별 느린 재생은 진단 보조로 제공하고 정상 속도 비교도 반드시 포함한다. 자동으로 가장 좋다고 판단하여 원본이나 이전 결과를 덮어쓰지 않는다.

### 필수 기능 F1: 원본 프레임 번호·시간 표시

진단 영상과 보고서에 클립 ID, 원본 프레임 번호(표시 순서, 0부터 시작), 원본 시작 기준 시간, 출력 프레임 번호·시간을 표시한다. VFR의 원본 시간은 프레임 번호/FPS로 추정하지 않고 실제 PTS에서 첫 표시 PTS를 뺀 값으로 계산한다. 원래 PTS와 time base도 보고서에 보존한다. 출력 프레임에서 선택된 원본 프레임으로의 매핑을 기록하여 프레임 제거·반복·변속 이후에도 문제 위치를 재현할 수 있게 한다. 최종 제작 영상에는 진단 표시를 넣지 않는다.

### 필수 기능 F2: 원본·보정본 동기 비교

1단계에는 원본 연결본과 보정본을 한 화면에 나란히 배치한 비교 영상을 만든다. 같은 경계를 시간 0으로 정렬하고 동일한 경계 상대 시간에서 양쪽을 표시한다. 보정으로 길이가 달라져 비교 범위를 벗어난 쪽은 빈 영역과 범위 밖 표시를 사용하며 임의로 정지 프레임을 붙이지 않는다. 변속한 양쪽은 같은 재생 시점에도 서로 다른 원본 프레임을 보여줄 수 있으므로 F1의 원본·출력 시간을 각각 표시한다. 이 비교를 만들기 위해 추가로 배속을 바꾸지 않는다.

4단계 UI에서는 공통 재생 위치로 재생·일시정지·탐색·경계 구간 반복·출력 프레임 단위 앞뒤 이동을 제어한다. 느린 재생은 양쪽에 같은 비율로 적용하며 정상 속도 비교를 기본으로 한다.

### 필수 기능 F3: 클립별·연결부별 보정 제외

클립의 보정 활성 여부와 경계의 보정 활성 여부를 별도로 지정한다. 클립 보정을 끄면 해당 클립의 시간 압축·국소 속도 조절·경계 중복 제거를 제외한다. 그 클립에 닿는 경계 보정도 양쪽 모두 적용하지 않는다. 경계 보정만 끄면 해당 경계의 중복 제거·국소 조절만 제외하며 양쪽 클립의 목표 시간 압축은 유지한다. 제외는 클립을 연결 목록에서 삭제한다는 뜻이 아니다.

명시적 비활성화는 자동 보정 추천보다 우선한다. 보정을 끈 클립에 원본 길이와 다른 목표 시간을 요구하면 설정 충돌로 반환하고 조용히 압축하거나 목표 시간을 무시하지 않는다. 비활성화 상태에서도 공통 출력 규격을 위한 FPS·해상도 변환과 인코딩은 수행될 수 있으며 이를 보고한다. 설정값과 실제 적용·제외 사유를 기록한다.

## 5. 2단계: 후반 중심 시간 압축

### 사용자 설정

- 원본 길이 D: 분석으로 얻는다.
- 목표 길이 T: 사용자가 지정한다.
- 보호 구간 P: 원본 시작부터 정상 속도로 유지할 구간.
- 가속 전환 폭, 허용 최대 배속, 연결부 조절 범위·강도.

압축은 기본적으로 0 ≤ P < T ≤ D 조건을 요구한다. T=D이면 별도 요구가 없는 한 시간 압축을 생략한다. T>D인 늘리기는 초기 범위 밖으로 명확히 거절한다. 보호 구간을 몰래 줄여 목표 시간을 맞추지 않는다.

예: D=10, T=4, P=2이면 남은 원본 8초를 출력 2초에 재생하므로 후반 평균 배속은 4배다. 시작을 1배속에서 부드럽게 가속한다면 후반 최대 배속은 평균 4배보다 커야 할 수 있다. 과도한 압축은 경고 또는 실행 불가로 처리하고 사용자에게 보호 구간·목표 시간 조정을 제안한다.

### 시간 매핑

출력 시간 t에 대응하는 원본 시간 s(t)를 정의한다. s(t)는 단조 증가하고, 보호 구간에서는 s(t)=t다. 이후에는 양의 속도 곡선 v(t)=ds/dt를 적분한다. 보호 구간 경계의 속도는 1배속에 연속적으로 연결하고, 전체 곡선의 적분이 원본 끝까지 도달하도록 수치적으로 계산한다.

배속 상한과 전환 폭을 검사하고 해가 없으면 명확한 오류를 낸다. 경계 보정과 전체 압축을 독립 필터로 무작정 누적하지 않고 하나의 최종 매핑으로 합성한 뒤 길이·단조성·보호 구간을 다시 검증한다.

영상은 이산 프레임이므로 마지막 표시 가능 프레임의 PTS와 컨테이너 길이를 구분한다. 출력 FPS에서 목표 프레임 수를 정하고, 첫·마지막 출력 프레임이 입력의 첫·마지막 표시 프레임에 대응하도록 프레임 스케줄을 만든다. 마지막 프레임 유지 시간까지 포함한 출력 길이를 검증한다. 타임스탬프 중복, 역행 및 끝 프레임 누락을 막는다.

초기 렌더러는 출력 프레임별 원본 위치에 따라 실제 원본 프레임을 선택한다. FFmpeg setpts 방식도 후보지만 CFR 변환 시 끝 프레임 보존 여부를 검증한 뒤 채택한다. 시간 단위와 time base를 혼용하지 않는다. 보간은 필수 기능이 아니며 잔상·형태 왜곡 위험 때문에 별도 옵션으로만 검토한다.

목표 길이는 출력 FPS의 한 프레임 단위로 양자화된다. 요청 시간, 실제 시간, 차이를 보고하며 기본 허용 오차는 한 출력 프레임 이내다. 공유 경계 이미지가 두 번 표시되어 멈칫할 경우 끝 이미지 보존과 다음 클립 프레임 배분을 함께 계산하고, 클립·전체 길이에 미치는 영향을 보고한다. 목표 시간을 맞추려고 마지막에 긴 정지 프레임을 덧붙이지 않는다.

### 필수 기능 F4: 전체 타임라인 시간 검증

클립별 요청 길이, 출력 프레임 예산, 최종 배치 구간 [시작, 끝), 실측 길이·오차와 경계별 중복 처리 프레임 수를 기록한다. 전체 요청 길이의 합과 최종 출력 길이도 비교한다. 출력 FPS를 기준으로 전체 프레임 예산을 먼저 계산하고 클립별 반올림 오차를 배분하여, 개별·전체 오차가 각각 한 출력 프레임을 넘지 않게 한다.

공유 경계 프레임은 전체 타임라인에서 한 번만 계산하며 소속과 배분 규칙을 보고한다. 중복 제거 후 단순히 총길이가 줄어든 상태를 통과시키지 않고, 보호 구간·끝 이미지·보정 제외 조건을 지키며 남은 프레임 스케줄을 재계산한다. 제약을 동시에 만족할 수 없으면 오류로 보고한다. 최종 디코딩 결과의 프레임 수·PTS·마지막 프레임 표시 종료 시각으로 프레임 공백·겹침·누적 오차를 검사한다.

### 오디오 정책

영상 움직임 검증이 우선이며 초기 테스트 출력은 오디오 제외를 명시한다. 입력 오디오 존재는 보고한다. 원본 오디오를 그대로 복사해 변속 영상과 어긋나게 만드는 처리는 금지한다. 동기화 오디오가 필요하면 가변 배속·피치 유지·경계 크로스페이드 처리를 별도 구현하고 검증한다. 이 기능 전에는 오디오 유지 요청을 지원하지 않는다고 명확히 반환한다.

## 6. 3단계: JSON 작업 정의

아래는 버전 1 작업 정의 예시다. 지원 필드·기본값과 제한은 구현 README 및 검증 보고서로 확인한다. 1단계 분석 결과 JSON 보고서와 3단계 사용자 입력 JSON은 별개다.

```json
{
  "schema_version": 1,
  "output": {
    "directory": "outputs/job_001",
    "fps": 30,
    "audio_mode": "mute"
  },
  "clips": [
    {
      "id": "clip_01",
      "path": "inputs/clip_01.mp4",
      "correction_enabled": true,
      "target_seconds": 4.0,
      "protect_seconds": 2.0,
      "max_speed": 8.0,
      "ramp_seconds": 0.5
    },
    {
      "id": "clip_02",
      "path": "inputs/clip_02.mp4",
      "correction_enabled": true,
      "target_seconds": 5.0,
      "protect_seconds": 3.0,
      "max_speed": 3.0,
      "ramp_seconds": 0.5
    }
  ],
  "boundaries": [
    {
      "from": "clip_01",
      "to": "clip_02",
      "enabled": true,
      "mode": "manual",
      "window_seconds": 0.5,
      "strength": 0.3,
      "local_speed": true,
      "duplicate_policy": "review"
    }
  ],
  "internal_motion": {
    "reports": [],
    "selected_ids": [],
    "excluded_ids": []
  }
}
```

상대 경로는 JSON 파일이 있는 디렉터리를 기준으로 해석한다.

`clips[].correction_enabled`와 `boundaries[].enabled`는 생략 시 true다. false의 의미와 우선순위는 F3를 따른다. 프레임 매핑·동기 비교 기준·최종 타임라인 검증 결과는 결과 보고서에 저장한다.

알 수 없는 설정, 중복 ID, 없는 파일, 잘못된 수치, 인접하지 않은 클립 사이의 경계 지정, 입력·출력 경로 충돌을 실행 전에 검증한다. 설정·입력 식별 정보·도구 버전·실측 시간·성공 여부를 결과 보고서에 남긴다. 누락된 클립을 조용히 건너뛰고 연결 성공으로 처리하지 않는다. 실패 시 중간 결과를 구분하고 전체 명령은 비정상 종료 코드를 반환한다.

## 7. 4단계: UI

클립 목록과 순서 변경, 원본·목표 시간 표시, 보호 구간 지정, 속도 곡선 표시, 경계별 비교 재생, JSON 불러오기·저장, 일괄 출력, 진행률·취소·오류 표시를 갖춘다. 정밀한 설정이 정상 작동한 뒤 구현하며 범용 편집기 타임라인은 만들지 않는다. 인코딩 작업은 UI 스레드와 분리한다.

F1의 원본·출력 위치 표시, F2의 동기 비교·반복·프레임 이동, F3의 개별 보정 토글과 제외 사유, F4의 클립별 배치 시간·총길이·오차 표시를 제공한다. 설정 변경 후 이전 결과를 최신 결과처럼 표시하지 않으며 재계산·렌더링 필요 상태를 알린다.

## 8. 검증·운영 원칙

구현 작업자와 검증 작업자를 분리한다. 조율 담당이 작업 범위와 완료 기준을 지정하고, 각 작업은 구현·자체 테스트 → 독립 검증 → 결함 수정·재검증 → 통과 보고 순서로 진행한다. 검증 작업자는 제품 코드를 직접 고치지 않고 재현 절차와 증거를 구현 담당에게 전달한다. 상세 역할·인계 양식·판정 기준은 [작업지시서의 역할과 책임](WORK_INSTRUCTIONS.md#역할과-책임)을 따른다.

작업 순서는 A1 → A2 → A3 → A4 → B1 → B2 → C → D이며 각 작업 단위에서 독립 검증한다. 검증할 코드 상태를 식별하고 검증 중 같은 파일을 동시에 수정하지 않는다. 필수 검증이 미실행이면 통과로 처리하지 않는다. 2026-10-12 사용자 지시에 따라 기술 검증 후 후속 코드를 순차 구현한다. 실제 시각 품질 승인 여부는 별도 기록하며 미확인을 이유로 B1 이후 코드 작업을 중단하지 않는다.

자동 검증: 입력 보존, 시작·끝 프레임 대응, 목표 길이, 보호 구간 속도, 단조 PTS, 디코딩 가능 여부, 결과 프레임 수, 실패 종료 코드.

합성 샘플: 동일 경계·일정 이동, 경계 중복 정지, 속도 차이, 방향 충돌, 끝 이미지 미세 차이, 서로 다른 FPS, 무음·유음 입력. 2단계에는 10→4초와 6→5초, 불가능한 보호 구간·배속 상한을 포함한다.

실제 검증: 사용자의 순서가 있는 3~4개 영상으로 정상 속도 비교를 보고 멈칫함·급가속·끝 이미지 유지·핵심 동작 가독성을 확인한다. 자동 점수가 개선되어도 육안상 악화되면 통과시키지 않는다.

원본·기존 결과는 보호한다. 임시 디렉터리는 작업별로 분리하고 성공 결과는 원자적으로 확정한다. 실패·취소 시 진단 로그를 남기되 입력 파일은 제거하지 않는다. 외부 명령은 인수 배열로 실행하고 셸 문자열 보간을 피한다. 프레임 전체를 메모리에 쌓지 않으며 초기 구현은 순차 처리로 자원을 제한한다.

현재 구현·검증 범위는 진행 보고서로 추적하며 실제 시각 품질·성능·지원 OS는 검증한 범위에서만 주장한다. 코드 작성, 커밋, GitHub 업로드는 이 문서 작성과 별도 작업이다. GitHub 업로드는 사용자가 명시적으로 지시한 뒤 수행한다.

## 9. B1·B2·C·D 추가 설계 (2026-10-12)

이번 순서는 B1 목표 시간 압축 → B2 내부 의심 구간 검토·선택 보정 → C JSON 저장·일괄 실행 → D UI 연동이다. 각 단계는 구현 담당과 별도 검증 담당이 순차 인계한다. 이전 A4 품질 확인 대기는 사용자의 후속 코드 진행 지시로 해제하며 사용자 품질 승인 자체를 받은 것으로 해석하지 않는다.

### B1 기본 설정과 보호 우선순위

초반 보호 시간은 명시적인 입력이다. 첫 실제 후보에서 미지정이면 1초를 초기값으로 사용하고 설정·보고서·UI에 표시한다. 이는 핵심 동작의 의미 분석이 아니다. 가속 전환은 연속적인 속도 곡선을 사용하며 원본 마지막 표시 프레임까지 도달한다. 원본 길이와 목표가 같으면 압축을 생략한다. 보호 구간과 충돌하는 경계 조절은 보호 구간 우선으로 제한하거나 제외 사유를 기록한다. 경계 후보의 속도는 원본 움직임 측정값에 시간 매핑의 경계 배속을 반영하여 계산한다. 다음 클립의 시작이 보호되어 있으면 조절 가능한 앞 클립 끝을 그 고정 속도에 맞추는 후보를 만든다. 원본 속도만으로 압축 후 경계를 조절하지 않는다.

### B2 내부 의심 구간과 선택 보정

반복 프레임·짧은 정지·급격한 움직임 속도 변화를 저해상도 순차 분석한다. 보고서에는 안정적인 구간 ID, 종류, 원본 시간 범위, 근거 수치, 원본 SHA256, 분석 버전·설정을 보존한다. 탐지는 검토 후보이며 결함 판정이 아니다. 형태 왜곡 복원이나 카메라 안정화는 이번 기능 범위에 포함하지 않는다.

흐름은 의심 구간 표시 → 원본·후보 비교 → 적용 여부 선택이다. 후보 생성은 최종 적용과 분리한다. 기본은 모든 후보 미선택이며 선택 ID만 최종 매핑에 반영한다. 원본 해시·분석 식별 정보가 달라지면 저장된 선택을 재사용하지 않는다. 겹치는 선택은 명확하게 거절하고 제외가 선택보다 우선한다.

보정은 구간 양 끝을 고정한 단조 시간 매핑으로 국소 속도를 완화하는 후보를 만든다. 순수 정지 프레임에서 새 움직임을 생성하지 않는다. 보호 구간·끝 프레임·배속 상한·전체 예산과 합성하여 제약을 다시 검사한다. 선택해도 프레임 양자화로 출력이 달라지지 않으면 적용 효과 없음을 보고한다. 비교는 같은 출력 시계를 사용하고 원본 위치를 각 화면에 표시하며 구간 밖은 검정으로 표시한다.

### C와 D 연동

JSON은 시간 압축 설정, 경계 옵션, 내부 분석 출처·선택·제외 ID를 저장한다. 잘못된 설정과 오래된 분석은 렌더링 전에 거절한다. UI는 같은 처리 엔진을 호출하고 내부 후보 목록·근거·비교·선택 체크와 보호 시간·목표 시간 편집을 제공한다. 선택 변경 후 이전 출력은 오래된 결과로 표시한다. 작업은 UI 스레드와 분리하며 진행·취소·오류와 결과 파일 위치를 보여준다.

제작 계획 `I2V_30Clips_Master.json`은 실행 작업 JSON과 별개다. 로컬 MP4를 먼저 고른 뒤 파일명의 장면·컷(`01_02` 또는 `SC01 · 01-02`)과 계획 `records[].scene`·`records[].cut`을 맞춰 `edit_duration_s`만 Target으로 가져온다. 계획에는 실제 MP4 경로가 없으므로 경로·순서·기존 경계 선택을 덮지 않는다. 누락·중복·시간 불일치를 사전에 거절하고, 가져온 결과는 기존 작업 JSON으로 따로 저장한다. CSV와 HTML은 같은 편집 계획의 검토 자료이며 영상 처리 명령으로 해석하지 않는다.

### 실제 결과 목표

코드 검증 후 SC01 01-02/01-03/01-04를 3·4·4초, 총 11초로 만든다. SC01 01-05/SC02 02-01은 4·4초, 총 8초로 만든다. 뒤 묶음은 장면이 달라 공유 이미지를 가정하지 않는다. 최종 출력은 초반 1초 보호의 명시적 후보 설정으로 시작하고 내부 보정은 선택 전까지 미적용이다. 소스·설정·프레임 매핑·실측 길이를 보고하여 이후 품질 조정이 가능하게 한다.
